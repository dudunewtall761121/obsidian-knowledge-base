# 知识库维护手册

> 本目录是团队的「第二大脑」：沉淀可复用知识，供所有 Agent 与成员检索引用。
> 版本：v1.0 · 关联：[Vault 入口](../00-Vault入口.md)

## 1. 知识库是什么、不是什么

**是什么**
- 任务产出中提炼出的**元信息**（方法、结论、踩坑、决策依据）
- 跨任务可复用的资产，不随单个任务归档而失效
- 所有 Agent 的共享上下文：启动任务前先检索，避免重复造轮子

**不是什么**
- 不是任务产出的副本（原文件留在工作台任务目录）
- 不是草稿箱（不收未经验证的想法）
- 不是聊天记录（不收过程性讨论）

## 3. 知识卡片标准格式

每条知识必须使用 frontmatter + 正文结构，否则审核不通过。

```markdown
---
type: best-practice        # best-practice | research | decision | glossary
tags: [内容/结构, 技术/部署]  # 标签，见第 6 节标签体系
source: "任务编号"           # 来源任务编号
created: 2026-11-09         # 创建日期
status: draft               # draft | reviewed | archived
---

## 场景
（什么情况下会用到这条经验）

## 做法
（具体怎么操作，3-5 条 bullet）

## 结果
（效果如何，数据或反馈）

## 关联
- 原始任务：[[任务编号]]
- 相关知识：[[相关知识卡片]]
```

**必填项**：type、tags、source、created、场景、做法。其余按需。

## 4. 谁写、谁审、谁整理

| 角色 | 职责 |
|---|---|
| 执行层 | 任务产出末尾写「可复用经验」段落（3-5 条 bullet，≤200 字） |
| 知识研究员 | 每周整理上周关闭任务的经验，去重、补 frontmatter、建立交叉链接 |
| 质量审核员 | 抽检 20%，不合格打回重写 |
| DOT 连接器 | 任务归档时检查「可复用经验」段落是否存在；每周一生成待整理清单 |

**触发条件**：只有「下一个任务大概率会用到」的经验才沉淀，不为了完成 KPI 而写。

---

## 5. 审核标准（三条硬性门槛）

1. **可复用性**：能回答「下一个什么任务会用到它」，答不上来不收；
2. **可验证性**：必须链接到原始任务产出（`source` 字段 + 正文中的 `[[任务编号]]`），无来源不收；
3. **简洁性**：单条知识正文不超过 300 字，超过说明没提炼好。

## 6. 标签体系

| 领域 | 细分 |
|---|---|
| `#内容/` | 结构、话术、风格、选题 |
| `#技术/` | 部署、Git、前端、后端、工具 |
| `#设计/` | 视觉、排版、动效、规范 |
| `#流程/` | 派单、审核、归档、同步 |
| `#决策/` | 终裁、特批、方向 |
| `#踩坑/` | 冲突、回滚、兼容性 |
| `#项目/` | active、paused、planning、archived（项目状态） |

新增标签须在本手册第 6 节登记，不得临时造标签。

## 7. Agent 读写协议

### 读取

```
启动任务前：
  git pull --rebase
  检索 03-知识库/ 相关分类 + 标签
  记录引用的知识卡片到任务包「参考资料」段
```

### 写入

```
任务产出末尾追加：
  ## 可复用经验
  - [场景] ...
  - [做法] ...
  - [结果] ...
```

### Git 冲突处理

- push 失败时重新 `git pull --rebase`
- 仍有冲突时，将冲突文件另存为 `<原名>.conflict`，推送本地版本
- **禁止 Agent 自动 merge**

## 8. 生命周期

| 状态 | 含义 | 流转 |
|---|---|---|
| `draft` | 刚整理，未审核 | → `reviewed` |
| `reviewed` | 审核通过，可被引用 | 半年未被引用降级为 `archived` |
| `archived` | 过期或不再适用 | 移至归档目录或删除 |
